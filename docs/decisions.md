# 결정 기록

작업규칙 12: STEP 이 끝날 때마다 결정과 이유를 한 줄씩 추가한다.

## STEP 0 — 확정된 열린 결정 (PRD 부록 D)

- **백엔드 = 경로 A (Supabase)** — 슬롯 유일성·익명 강제·80자 제한이 전부 스키마 제약(`UNIQUE`, `CHECK`)으로 박혀서, 코드가 도메인 규칙을 우회할 표면이 사라진다. Firestore는 같은 보장을 코드 규율로 유지해야 한다.
- **스타일 = CSS Modules** — Tailwind의 arbitrary value(`w-[163px]`)가 마크업에 값을 눌러붙게 만들어 작업규칙 8·9(픽셀·hex 하드코딩 금지)를 구조적으로 무너뜨린다. CSS 변수는 값이 반드시 `styles/`를 거치게 강제한다.
- **슬롯 배정 = 서버 배정** (빈 슬롯 중 랜덤) — 피그마가 이미 하단 CTA `Add Grape` 버튼 1개로 그려져 있고, 서버가 재시도하면 충돌이 사용자에게 보이지 않는다. §3 "방문자 마찰 = 0" 원칙에 맞고 재시도 UI가 통째로 불필요해진다. `UNIQUE(page_id, slot_index)` 는 그대로 유지 — 서버 재시도 루프의 정확성을 보장하는 게 그 제약이다.
- **페이지 용량 = 15알** — `data/slot-layout.ts` 길이 == `capacity` 를 STEP 2에서 테스트로 고정한다.
- **로그인 식별자 = 합성 이메일** (`{loginId}@grapevine.local`) — Supabase Auth는 이메일이 필수인데 §5.4 피그마는 `ID / PASSWORD` UI다. 내부만 이메일로 매핑해 UI를 지킨다. 비밀번호 재설정은 MVP 비목표라 부작용 없음.
- **Main 영상 = 5초** — 전 프레임 키프레임(`-g 1`) 인코딩이 용량을 3~5배 부풀려 15MB 예산이 길이를 강하게 제약한다. 길이를 먼저 못박고 촬영·렌더한다.
- **칭찬 80자 = 코드포인트 기준** — 클라 카운터(`Array.from(s).length`)와 PG `char_length` 를 일치시킨다. grapheme 기준으로 세면 이모지에서 클라/서버가 어긋나 Send가 조용히 실패한다.
- **주인의 칭찬 삭제 = MVP 없음, 스키마에 필드도 두지 않음** — `deletedAt` 을 "나중에 쓸까 봐" 넣으면 모든 조회에 필터가 따라붙는다. 필요 시 SQL로 수동 처리.
- **스팸 방지 = MVP 없음, STEP 20에서 IP 해시 레이트리밋만** — 슬러그가 추측 불가 랜덤이라 무차별 유입 표면이 없다. 쿠키 가드는 우회가 쉬운데 마찰만 늘어 §3 원칙에 반한다.
- **모바일 폴백 = Main(`/`) 한정** — `/v/[slug]`·`/my` 는 영상 없이도 완전 동작해야 한다. 링크 공유형이라 모바일 유입이 실제로 도달하는 곳은 Main이 아니라 `/v/[slug]` 이므로, 연출 실패가 제품 실패로 번지지 않게 격리한다.
- **스크럽 폴백 발동 = 3단 게이트** — ① `prefers-reduced-motion` → 정적 ② `saveData`/2g·3g → 정적 ③ 마운트 직후 seek 실측(p95 > 100ms 또는 단일 seek 400ms 타임아웃) → WebP 시퀀스 + canvas. UA 스니핑을 1차 기준으로 쓰지 않는 이유는 iOS가 개선되면 프로브가 자동으로 통과하기 때문이다.

## STEP 1 — 스캐폴드

- **`create-next-app` 대신 수작업 스캐폴드** — `CLAUDE.md` 가 create-next-app 의 허용 파일 목록에 없어 실행이 막힌다. 우회해도 데모 페이지·SVG·README 등 스코프 밖 파일을 생성해 되지워야 한다.
- **환경변수에 `NEXT_PUBLIC_` 접두사를 쓰지 않음** — 접두사가 붙는 순간 Next가 값을 클라 번들에 인라인한다. "모든 DB 접근은 서버 경유" 설계를 변수 이름 수준에서 강제한다.
- **`server-only` 패키지 도입** — service role 키가 클라이언트 번들에 새면 DB 전체가 열린다. 0바이트 빌드타임 가드로 `lib/supabase.ts` 를 서버 전용으로 못박는다.
- **Supabase 클라이언트를 싱글턴 캐싱하지 않음** — 서버리스에서 요청 간 인스턴스를 공유하면 세션이 섞인다.
- **`@supabase/ssr`·`jsdom`·ESLint 는 지금 설치하지 않음** — 각각 STEP 4(계정), 디자인 패스(컴포넌트 테스트) 소관. 스코프 밖.
- **`styles/globals.css` 를 빈 플레이스홀더로 둠** — 리셋·색조차 넣지 않는다. 작업규칙 8·9상 STEP 1은 디자인 값을 정할 자리가 아니다. STEP 10에서 토큰과 함께 채운다.
- **`turbopack.root` 명시** — 홈 디렉터리의 무관한 `package-lock.json` 때문에 Next가 워크스페이스 루트를 잘못 추론한다.
- ⚠️ **한시적 규칙 예외:** 라우트 7개에 `"GRAPEVINE"` 문자열을 직접 박았다. 절대규칙 6(문구는 `data/copy.ts`)의 예외다. 이건 제품 카피가 아니라 "이 라우트가 살아 있다"는 스캐폴드 마커이고, `data/copy.ts` 는 아직 존재하지 않는다. **STEP 7(회색박스)에서 실제 카피로 전량 교체하며 그때 이 마커는 0개가 되어야 한다.**

## STEP 2 — 모델·스키마·슬롯좌표

- **`models/` 는 단일 파일** — "import 금지"를 문자 그대로 지키려면 `PageView` 가 `Grape` 를 참조하는 순간 파일을 나눌 수 없다. 5개 타입을 `models/index.ts` 하나에 둬서 import 문이 0개다.
- **`PageSlot` 타입을 이름 붙여 분리** — PRD §8 은 `slots: Array<{ slotIndex; grape }>` 인라인이지만, repositories/components 양쪽이 이 모양을 참조하므로 이름이 필요하다. 구조는 PRD 그대로.
- **제약에 전부 명시적 이름을 붙임** — `repositories/` 어댑터가 제약 이름으로 도메인 에러를 판별한다. Postgres 자동 생성 이름에 의존하면 이름이 바뀔 때 에러 매핑이 조용히 깨진다. 로컬 PG16 으로 실측한 값: 슬롯 충돌 → **SQLSTATE `23505` / `grapes_slot_key`**, 80자 초과 → **`23514` / `grapes_message_length_check`**.
- **`UNIQUE(vine_id, page_index)` 추가** — 요청 목록에 없었지만 PRD §7-3 페이지 자동 증설의 정확성이 여기 걸린다. 마지막 두 칸이 동시에 채워지면 "다음 페이지 생성" 판정도 함께 경쟁하므로, 이 제약이 없으면 같은 page_index 가 두 번 생길 수 있다.
- **`UNIQUE(vines.owner_id)` 추가** — PRD §7-1 "판은 사용자당 1개"를 스키마로 강제. Create 버튼 더블클릭도 이걸로 막힌다.
- **전 테이블 RLS enable, 정책 0개** — anon/authenticated deny-all. service_role 만 통과하므로 "모든 접근은 서버 경유" 설계가 DB 레벨에서 강제된다.
- **`users` 를 `auth.users` 와 아직 연결하지 않음** — PRD §8 그대로 독립 테이블. FK(`id references auth.users(id)`)는 STEP 4(계정)에서 추가한다.
- **`slot_index` 상한은 스키마로 강제하지 않음** — 상한이 `vine_pages.capacity` 라 테이블 CHECK 로 표현할 수 없다. STEP 5 의 `attach_grape` RPC 가 대조한다. 하한(`>= 0`)만 CHECK.
- **`vine_pages` 에 `created_at` 없음** — PRD §8 `VinePage` 에 없다. 순서는 `page_index` 로 정해지므로 필요도 없다. 모델과 DB를 어긋나게 두지 않는다.
- **`message` 하한 미설정** — 요청 스펙이 `char_length(message) <= 80` 이라 그대로 따랐다. 빈 문자열이 통과하므로 **STEP 5 서비스 검증에서 막아야 한다.**
- **`copy.ts` 는 PRD 에 문자 그대로 있는 문구만 채움** — About 타이틀·에러·빈 상태는 PRD 에 문안이 없어 지어내지 않고 TODO. 작업규칙 8.
- **`slot-layout.ts` 좌표계 규약 확정** — xPct/yPct 는 알의 **중심**, sizePct 는 **지름이며 컨테이너 폭 대비**. 지름을 높이 대비로 잡으면 종횡비가 바뀔 때 알이 타원이 된다. 값 수령 시 이 규약을 함께 확인할 것.
- **좌표 미수령 상태를 `it.todo` 로 표시** — 배열이 비어 구조 검사가 공허하게 통과하므로, 개수 검사만 todo 로 남겨 "아직 안 끝났다"를 테스트 결과에 드러낸다. (좌표 수령 후 해제됨)

## STEP 2b — 슬롯 좌표 수령 (Figma 201:753)

- **15알 확정, PRD 가 맞았다** — 프레임에 ellipse 노드는 **16개**지만 `Ellipse 5009`(201:764)가 `Ellipse 5007`(201:768)과 x/y/size 가 완전히 동일해 정확히 겹쳐 있다. 스크린샷으로도 원은 15개만 보인다. 초기에 지적했던 "5002~5017 = 16개인데 PRD 는 15알" 불일치의 정체가 이것이다. **5009 를 제외**했고, 피그마 쪽 잔여 레이어이므로 정리 권장.
- **slotIndex = Ellipse 번호 오름차순** (5002→0 … 5017→14) — 채워지는 순서와 무관하다(배정은 서버 랜덤). 이 순서를 쓴 이유는 디버깅 시 슬롯 ↔ 피그마 노드를 역추적할 수 있어서다. 각 항목에 원본 노드 ID와 px 를 주석으로 남겼다.
- **환산식** — `xPct = (x + 163/2) / 1536 × 100`, `yPct = (y + 163/2) / 771 × 100`, `sizePct = 163 / 1536 × 100`. 소수 3자리 반올림(오차 < 0.008px).
- **`SOURCE_FRAME` 상수 추가** — 환산 기준(1536×771)을 코드에 남겨야 나중에 역산이 가능하다.
- **골든 역산 테스트 추가** — 피그마 원본 px 를 테스트에 박아 두고 % → px 로 되돌려 대조한다. 누가 % 값을 손으로 "조정"하면 즉시 깨진다. 허용 오차는 0.05px(`toBeCloseTo(_, 1)`) — 3자리 반올림 오차 0.008px 보다 크고 의미 있는 이동보다는 작다.
- ⚠️ **컨테이너 종횡비 1536:771 (≈1.992) 을 유지해야 한다** — x는 폭 대비, y는 높이 대비로 환산했으므로 종횡비가 달라지면 알과 배경 넝쿨이 어긋난다. STEP 7·12 구현 제약.
- **환경변수 이름을 Supabase 대시보드 현재 라벨에 맞춤 (STEP 2b)** — `SUPABASE_ANON_KEY`/`SUPABASE_SERVICE_ROLE_KEY` → `SUPABASE_PUBLISHABLE_KEY`/`SUPABASE_SECRET_KEY`. 대시보드가 주는 이름과 코드가 달라 매번 머릿속에서 번역해야 했다. 함수 이름(`createAnonClient`/`createServiceRoleClient`)은 Postgres **역할** 기준이라 그대로 뒀다 — RLS 를 따질 때 중요한 건 키가 아니라 역할이다.

## STEP 2c — 마이그레이션 원격 적용 (Supabase `ptnnqflkhmjhaciafjmn`)

- **Direct connection 을 쓰지 않는다. Pooler 를 쓴다.** `db.<ref>.supabase.co` 는 **AAAA(IPv6) 레코드만** 있고 A 레코드가 없어서, IPv4 전용 네트워크에서는 이름 해석부터 실패한다. 대신 `aws-1-ap-northeast-2.pooler.supabase.com:5432`(session mode) 로 붙는다. 리전과 프리픽스는 실측으로 확정했다 — `aws-0` 은 `tenant not found`, `aws-1` 은 성공.
- **DB 비밀번호는 영숫자로만 만든다** — `@ / : ? # & %` 가 들어가면 `--db-url` 에 퍼센트 인코딩이 필요해지고, 인코딩 실수와 진짜 비밀번호 오류가 같은 `password authentication failed` 로 보여서 원인 분리가 어려워진다.
- **PAT 없이 `--db-url` 로 적용** — `supabase db push --db-url` 은 PAT 이 필요 없고, 마이그레이션 이력은 원격 DB 의 `supabase_migrations.schema_migrations` 에 기록되므로 이력 관리도 그대로 된다. PAT 은 `link` 편의용일 뿐이다.
- **`db push` 의 Docker 경고는 무시해도 된다** — 로컬 마이그레이션 카탈로그 캐시(`db diff` 용)를 만들지 못한다는 뜻이고 push 자체와 무관하다.
- ⚠️ **RLS deny-all 에서 SELECT 는 403 이 아니라 `[]` + HTTP 200 을 반환한다.** 정책이 없으면 PostgREST 는 "거부"가 아니라 "0행"으로 응답한다. 실제 데이터를 커밋해 두고 확인한 결과 publishable key 로는 4개 테이블 전부 `[]`, secret key 로만 보인다. **데이터는 새지 않지만, `/v/[slug]` 공개 조회를 publishable key 로 처리할 수는 없다** — 모든 읽기도 서버에서 service_role 로 해야 한다. 확정된 설계 그대로다.
- **원격 DB 에서 제약 14종 재검증 완료** — 전부 트랜잭션 안에서 실행하고 롤백해 잔여 행 0. 로컬 PG16 결과와 동일하다.

## STEP 3 — 데이터 계층 (repositories / services)

- **`addGrape(pageId, slotIndex, payload)` 는 "슬롯 선택"을 하지 않는다** — 요청 시그니처대로 slotIndex 를 받는 **원자 연산**이다. 확정된 설계(서버가 빈 슬롯 중 랜덤 배정)의 선택·재시도 루프는 그 위 services/ 소관이고, 이 메서드는 "이 슬롯을 원자적으로 점유하라"만 책임진다. 두 관심사를 한 메서드에 넣으면 재시도 정책을 바꿀 때마다 데이터 계층을 건드리게 된다.
- **인터페이스에 트랜잭션을 노출하지 않음** — `beginTransaction()` 같은 메서드를 두면 Postgres/Firestore 중 한쪽 모델에 종속된다. 원자성 확보 방식은 어댑터 내부 디테일로 둔다.
- **에러는 예외로 던지되 도메인 타입으로 번역** — `lib/errors.ts` 의 `DomainError` 계층. 어댑터가 SQLSTATE + **제약 이름**으로 판별해 번역한다. SQLSTATE 만으로는 부족한 이유는 grapes 의 CHECK 가 4개라 전부 `23514` 로 오기 때문 — 어느 규칙이 깨졌는지는 제약 이름으로만 알 수 있다. STEP 2 에서 모든 제약에 이름을 붙인 이유가 여기서 회수된다.
- **슬러그는 CSPRNG** — `crypto.getRandomValues`. 슬러그가 `/v/[slug]` 의 유일한 접근 통제 수단(절대규칙 4: 세션 무관 공개)이라 `Math.random()` 은 부적격이다. 알파벳은 32자로 고정: `0/O`·`1/l` 을 빼서 눈으로 헷갈리지 않게 하고, 길이가 정확히 32(=256/8)라서 `byte % 32` 에 모듈로 편향이 없다. 32^10 ≈ 2^50.
- **슬러그 충돌은 사전 조회가 아니라 "써 보고 재시도"** — 조회 후 삽입은 그 사이가 그대로 경쟁 구간이라 충돌을 못 막는다. 실제 방어선은 `UNIQUE(vines.slug)` 이고 `withUniqueSlug` 는 그 실패를 흡수할 뿐이다. 슬롯 점유와 정확히 같은 구조다.
- **`slugFactory` 를 생성자 주입** — PRD §7-10(테스트를 위해 주입 가능하게). 기본값은 `generateSlug`.
- ⚠️ **`createVine` 은 아직 원자적이지 않다** — vines 삽입과 vine_pages 삽입이 별도 문장이다. 페이지 삽입이 실패하면 "페이지 없는 판"이 남고 `UNIQUE(owner_id)` 때문에 재생성도 막힌다. 지금은 **보상 삭제**(vine 을 지우고 rethrow)로 막아 뒀지만 진짜 트랜잭션이 아니다. **STEP 5 에서 RPC 하나로 합쳐야 한다** — 페이지 자동 증설(절대규칙 2)도 같은 RPC 에 들어가므로 함께 처리한다.
- **`getPage` 는 DB 의 `capacity` 를 신뢰한다** — `PAGE_CAPACITY` 상수가 아니라 페이지 행의 값으로 슬롯 배열을 만든다. 상수는 레이아웃 쪽 진실이고 DB 가 저장 쪽 진실이다.
- **vitest 에 `server-only` alias 추가** — 이 패키지는 Next 번들러 밖에서 import 되면 throw 한다. no-op 으로 치환해야 서버 전용 모듈을 테스트에서 부를 수 있다.
- **원격 테스트는 자격증명 없으면 스킵** — `describe.skipIf`. 단 **describe 본문은 스킵돼도 실행**되므로 클라이언트 생성을 `beforeAll` 로 늦춰야 한다. 본문에서 만들면 스킵이 아니라 수집 단계 실패가 된다(실제로 한 번 밟았다).
- **테스트 뒷정리는 users 삭제 하나로** — FK cascade 로 vines → vine_pages → grapes 가 함께 지워진다.

## STEP 3b — 지적한 문제 해결

- **`createVine` 원자성 확보 — `create_vine` RPC** (`20260731010000`). plpgsql 함수 본문은 호출 문장 하나 안에서 실행되므로, `vine_pages` 삽입이 실패하면 `vines` 삽입도 함께 롤백된다. 보상 삭제를 걷어냈다 — 보상 삭제는 그 삭제 자체가 실패할 수 있어서 진짜 해결이 아니었다.
  **실증:** `vine_pages` 에 반드시 실패하는 트리거를 주입하고 `create_vine` 을 호출한 뒤 vines 행 수를 셌다 → 0. 전부 트랜잭션 안에서 하고 롤백했다.
- **슬러그는 여전히 TS 쪽에서 만든다** — RPC 는 주어진 슬러그로 점유만 시도하고, 충돌하면 `UNIQUE(vines.slug)` 위반을 그대로 올린다. 생성·재시도를 DB 로 내리면 `services/slug.ts` 가 백엔드에 묶여 경로 B 교체가 막힌다.
- **RPC 는 `security invoker`** — `definer` 로 만들면 이 함수 자체가 RLS 를 우회하는 구멍이 된다. invoker 라서 anon 이 호출하면 내부 INSERT 가 RLS 에 걸린다.
- ⚠️ **`revoke all ... from public` 은 Supabase 에서 듣지 않는다** (`20260731020000` 으로 수정). Supabase 는 `anon`/`authenticated` 에게 default privileges 로 EXECUTE 를 따로 부여하기 때문에 PUBLIC 에서 회수해도 두 역할은 그대로 남는다. **역할을 명시해 `revoke execute ... from anon, authenticated`** 해야 한다. 실측으로 잡았다 — 회수 전 anon 호출은 `42501 row-level security`(RLS 가 막음), 회수 후는 `42501 permission denied for function`(권한이 막음). 실제로 뚫린 적은 없지만 방어가 한 겹뿐이었다.
- **적용된 마이그레이션은 수정하지 않고 새 파일로 고친다** — 파일을 고치면 이 DB(이미 적용됨)와 새로 만든 DB(수정본 적용)의 스키마가 갈라진다.
- **`.rpc().returns<T>()` 는 스칼라 jsonb 반환에 쓸 수 없다** — supabase-js 가 배열 캐스팅으로 간주해 타입 에러를 낸다. 런타임은 정상이라 테스트만 돌리면 못 잡는다. 경계에서 `as` 캐스트 + 형태 확인으로 처리해, 형태가 어긋나면 매핑 중 TypeError 가 아니라 `RepositoryFailureError` 로 드러나게 했다.
- **`withUniqueSlug` 재시도 경로 테스트 6개 추가** — 왕복 테스트에서는 슬러그가 충돌하지 않아 재시도 루프가 한 번도 실행되지 않았다. 순수 함수라 주입만으로 덮인다: 충돌 후 재시도 성공 / 예산 소진 시 `SlugExhaustedError` / 마지막 충돌을 `cause` 로 보존 / **충돌이 아닌 에러는 재시도 없이 즉시 재던짐** / 첫 시도 성공 시 1회만 호출.

## STEP 4 — 계정 (auth + 라우트 가드)

- **가입은 `signUp()` 이 아니라 `admin.createUser({ email_confirm: true })`** — 이 프로젝트는 `mailer_autoconfirm: false`(이메일 확인 켜짐)인데 합성 주소 `{loginId}@grapevine.local` 은 메일을 받을 수 없다. `signUp()` 을 쓰면 확인이 영원히 끝나지 않아 **가입이 완료되지 않는다.** Admin API 로 확인된 사용자를 바로 만들면 메일이 나가지 않고 대시보드 설정도 건드릴 필요가 없다. 부수 효과로 **loginId 유일성이 공짜로 얻어진다** — loginId ↔ 이메일이 1:1 이라 GoTrue 의 이메일 중복 거절이 곧 `LoginIdTakenError` 다.
- **프로필은 트리거가 아니라 멱등 upsert(`ensureProfile`)** — `admin.createUser` 는 HTTP 호출이라 우리 SQL 과 한 트랜잭션에 묶는 것이 **원리적으로 불가능**하다. `auth.users` 트리거는 소유자가 `supabase_auth_admin` 이라 막힐 수 있고, 무엇보다 원자성을 흉내내봐야 반쪽이다. 대신 가입·로그인 **양쪽**에서 부르는 멱등 upsert 로 만들어 프로필 누락이 다음 로그인에 스스로 낫게 했다. 보상 삭제를 안 쓰는 이유는 STEP 3b 와 같다 — 보상 자체가 실패할 수 있다.
- **`users_auth_fkey` 는 실제로 생성 가능했다** — 계획 단계에서 권한이 막힐 수 있다고 봤으나, 트랜잭션 안에서 시험해 보고 가능함을 확인한 뒤 적용했다. 추측으로 우회하지 않았다.
- ⚠️ **FK 가 STEP 3 테스트 픽스처를 잡았다** — 임의 UUID 로 `public.users` 에 직접 넣던 방식이 이제 막힌다. 픽스처가 실재하는 auth 사용자를 만들도록 고쳤다. 뒷정리도 `admin.deleteUser` 한 번으로 `public.users → vines → vine_pages → grapes` 까지 cascade 된다. **FK 가 제 일을 한 것이므로 테스트를 고치는 게 맞다.**
- **폼은 Server Action 이 아니라 Route Handler** — 요청받은 검증이 전부 "HTTP 요청 → 상태코드/리다이렉트"라 Server Action(액션 ID + `Next-Action` 헤더 필요)으로는 정직하게 테스트하기 어렵다. 평범한 폼 POST 라 **JS 없이 동작**하는 것도 회색박스 단계에 맞다.
- **POST 후 리다이렉트는 303** — 302/307 은 메서드를 보존해서 브라우저가 `/my` 로 다시 POST 를 보낸다.
- **세션 확인은 `getUser()`, `getSession()` 금지** — `getSession()` 은 쿠키를 그대로 믿어 위조가 가능하다. `getUser()` 는 인증 서버에 토큰을 검증시킨다. 가드에 쓰는 값이라 반드시 후자.
- **Next 16 은 `middleware.ts` 가 deprecated, `proxy.ts` 로 개명** — 함수명도 `proxy`. `src/app` 구조라 파일은 `src/proxy.ts`. 빌드 출력에 `ƒ Proxy (Middleware)` 로 등록됨을 확인했다.
- **가드는 두 겹** — Next 문서가 명시적으로 경고한다: *"Always verify authentication and authorization inside each Server Function rather than relying on Proxy alone."* matcher 변경이나 라우트 이동으로 커버리지가 조용히 사라질 수 있으므로 `/my` 페이지가 세션을 **다시** 확인한다.
- **`proxy` matcher 는 `/my` 만** — `/v/[slug]` 가 목록에 **없다**는 사실이 절대규칙 4를 보장한다. "공개로 둔다"는 코드가 아니라 가드가 애초에 실행되지 않는 구조다.
- **로그인 실패는 아이디/비밀번호를 구분하지 않는다** — 구분하면 어떤 아이디가 존재하는지가 새어나간다.
- **loginId 는 `^[a-z0-9][a-z0-9._-]{2,29}$` 로 제한** — 이메일 local part 가 되므로 `@` 나 공백이 들어가면 주소 자체가 바뀌어 다른 계정에 붙을 수 있다.
- ⚠️ **잠정값 3개, 확정 필요** — ① `displayName` 상한 **40자**(PRD 에 값 없음. 확정되면 DB CHECK 로도 내려야 한다) ② `copy.auth.displayNameLabel` ③ `copy.auth.logOut`. ②③ 은 PRD §5.4 가 로그인 폼만 정의하고 가입 폼 문구를 주지 않아 회색박스용으로 임시로 넣었다. 피그마 가입 화면이 나오면 교체.
- **라우트 테스트는 실서버를 띄운다** — 가드는 단위 테스트로 못 잡는다. matcher 미적용, 쿠키 미전달 같은 실패가 전부 배선 문제라 진짜 HTTP 여야 의미가 있다. `next build && next start` 로 띄워 지연 컴파일 변수를 없앴다. 대가로 `npm test` 가 ~12초 늘었다.

## STEP 5 — 붙이기 · 슬롯점유 · 페이지증설

- **`attach_grape` RPC 1개로 점유 + 증설** (`20260731040000`) — 절대규칙 2. 앱에서 "삽입 → 카운트 → 증설"로 쪼개면 규칙 위반일 뿐 아니라 아래 경쟁이 생긴다.
- ★ **`select … from vine_pages where id = … for update` 가 이 함수의 핵심이다.** 잠금이 없으면: 13칸이 찬 상태에서 T1(슬롯 A)·T2(슬롯 B)가 동시에 들어오면 READ COMMITTED 라 서로의 미커밋 INSERT 를 못 본다 → **둘 다 "14칸, 아직 안 찼다"고 판정** → 15칸이 다 찼는데 **다음 페이지가 영영 안 생긴다** → PRD §7-3 이 금지한 "판이 끝났다" 상태.
  **실증:** 다른 세션이 그 페이지 행을 `FOR UPDATE` 로 잡고 있는 동안 `attach_grape` 를 호출하니 `select * from public.vine_pages` 에서 대기하다 statement timeout 으로 취소됐고, 잠금 해제 후 같은 호출이 성공했다. 잠금이 실제로 걸린다는 뜻이다.
  ⚠️ **잠금이 UNIQUE 를 대체하지 않는다.** 잠금 = 카운트의 정확성, `UNIQUE(page_id, slot_index)` = 슬롯 점유(절대규칙 1). 둘 다 필요하다.
  ⚠️ 잠금은 `grapes` 직접 INSERT 를 막지 못한다. **모든 알 삽입이 이 RPC 만 거친다**는 전제 위에서만 성립하므로 어댑터에 다른 경로를 만들지 말 것.
- **제약 없는 규칙은 커스텀 SQLSTATE 로 판별** — 주인 차단·슬롯 범위는 테이블 제약이 없어 제약 이름으로 구분할 수 없다. 메시지 문자열 매칭은 STEP 3 에서 배운 대로 취약하다. `GV001`(주인 차단) `GV002`(슬롯 범위) `GV003`(페이지 없음). 원격 DB 에서 그대로 올라오는 것을 먼저 확인하고 채택했다.
- **주인 차단(PRD §7-7)은 서비스가 아니라 RPC 안에서** — `p_actor_id`(null = 미로그인 방문자)를 받아 `vine.owner_id` 와 비교한다. 서비스 층에만 두면 나중에 리포지토리를 직접 부르는 경로가 생겼을 때 조용히 빠진다. **모든 알 쓰기가 반드시 통과하는 지점**에 둔다.
- **`slot_index` 상한을 여기서 강제** — STEP 2 에서 "상한이 `vine_pages.capacity` 라 테이블 CHECK 로 표현할 수 없다. STEP 5 RPC 가 대조한다"고 남겨 둔 항목을 회수했다.
- **`addGrape` 반환이 `Grape` → `{ grape, createdNextPage }` 로 바뀜** — 증설 여부를 호출자가 알아야 `1/2 >` 페이지네이션을 그릴 수 있고, 테스트도 이 값으로 증설을 직접 확인한다. STEP 3 테스트 1곳을 함께 고쳤다.
- **`getPageView(slug, pageIndex)` 는 `services/vine.ts` 에** — 슬러그로 판을 찾아 페이지를 여는 건 유스케이스지 저장소 원시 연산이 아니다. 리포지토리(A↔B 교체점)에는 `getVineBySlug` / `getPage` 원시 연산만 둔다.
- **테스트마다 자기 판을 새로 만든다** — 판을 공유하면 테스트끼리 슬롯을 뺏어 순서 의존이 생긴다.
- **거절이 부작용을 남기지 않는지도 확인한다** — 슬롯 중복 거절 후 기존 알이 그대로인지, 주인 차단 후 그 슬롯이 여전히 비어 있는지. "에러가 났다"만 보면 절반만 검증한 것이다.
- ⏸ **미결: 빈 메시지** — DB `CHECK` 는 `<= 80` 만 걸어서 빈 문자열이 통과한다. 이번 요청 목록에 없어 넣지 않았다. STEP 6(방문자 작성 플로우)에서 결정할 것.
- ⏸ **미결: 빈 슬롯 랜덤 배정 + 재시도 루프** — 확정된 설계지만 요청 범위 밖이라 미구현. `Add Grape` CTA 를 붙이는 STEP 6 소관. 현재 `addGrape` 는 "이 슬롯을 원자적으로 점유하라"는 원시 연산이다.

## STEP 6 — 공유링크 · 방문자 라우트

- **판단 로직을 순수 함수로 뽑았다** (`services/visitor.ts`) — 서버 컴포넌트 안에 조건문으로 흩어 두면 렌더를 돌려야만 검증된다. 분리하면 분기를 값으로 확인할 수 있고, STEP 7 에서 화면을 바꿔도 규칙은 그대로 남는다.
- **`clampPageIndex` 는 범위 밖을 "가장 가까운 경계"가 아니라 1 로 되돌린다** — 요청 스펙 그대로. 공유 링크는 아무나 손댈 수 있으므로 `?page=abc` `?page=0` `?page=1.5` `?page=0x2` 같은 값도 전부 첫 장으로 보낸다. 빈 화면이나 404 보다 낫다 (§3 방문자 마찰 0). `Number()` 는 `''`·`'1e3'`·`'0x2'` 를 통과시키므로 **정규식으로 정수만** 받는다.
- **CTA 판정은 주인 여부를 먼저 본다** — 주인이 꽉 찬 페이지를 보고 있을 때 "다음 장에서 쓰라"고 유도하면 갈 곳 없는 길을 안내하는 셈이다. 주인은 애초에 어느 페이지에도 못 쓴다 (PRD §7-7).
- **`buildShareUrl(origin, slug)` 은 origin 을 인자로 받는다** — 안에서 `location`/헤더를 읽으면 순수하지 않게 되고 배포 환경마다 다른 값을 테스트에서 재현할 수 없다. origin 은 `/my` 가 요청 헤더(`host` + `x-forwarded-proto`)에서 만든다 — 배포 도메인을 코드나 env 에 박지 않기 위해서다.
- **`copyToClipboard` 는 실패 시 false 를 돌려준다** — `navigator.clipboard` 는 보안 컨텍스트에서만 존재한다. 조용히 성공한 척하면 링크를 못 받은 걸 모르고 넘어가 판이 영영 안 채워진다.
- **`getVineByOwnerId` 를 리포지토리에 추가** — 슬러그 조회만 있어서 `/my` 가 자기 판을 찾을 수 없었다. 사용자당 1개(PRD §7-1)라 단수 반환.
- ⚠️ **React 는 인접 표현식 사이에 주석 노드를 끼운다** — `{a}/{b}` 가 `1<!-- -->/<!-- -->2` 로 렌더돼서 화면은 멀쩡한데 HTML 파싱이 깨졌다. 실제로 테스트가 실패해서 발견했다. 값을 **data 속성으로도** 내보내고 텍스트는 템플릿 리터럴 한 덩어리로 만들었다.
- **`/v/[slug]` 타이틀을 넣지 않았다** — PRD §5.9 는 `{주인이름}'s Vine` 인데 주인 `displayName` 조회는 이번 범위 밖이다. 슬러그를 이름 자리에 끼우면 틀린 값이 화면에 남으므로 아예 비웠다. `copy.othersVine.title(name)` 배선은 STEP 7.
- **라우트 테스트 파일을 `auth-routes.test.ts` → `routes.test.ts` 로 개명** — 방문자 라우트 검증이 붙어 이름이 맞지 않게 됐고, 서버 기동(~12초)을 파일마다 반복하지 않으려면 한 파일에 모아야 한다.
- ⏸ **미결 유지: 빈 메시지** — 작성 폼(Add Grape 모달)이 아직 없어 이번에도 결정 지점이 오지 않았다. STEP 7 에서.
- ⏸ **미구현: 빈 슬롯 랜덤 배정 + 재시도 루프, Create My Vine 배선** — 둘 다 이번 요청 범위 밖. 전자는 Add Grape 폼이, 후자는 빈 상태 화면이 생기는 STEP 7 소관이다. 지금 `/my` 는 판이 없으면 `no vine` 회색박스를 보여준다.

## STEP 6b — STEP 7 차단 요소 해소

- **빈 메시지를 스키마로 내렸다** — STEP 2 부터 "서비스에서 막아야 한다"고 미뤄 온 항목. 서비스에만 두지 않은 이유는 이 프로젝트의 원칙 때문이다. 슬롯 유일성·익명 강제·80자가 전부 제약으로 박혀 있어 규칙을 우회할 표면이 없는데 빈 메시지만 예외로 둘 근거가 없다.
- ⚠️ **첫 제약이 틀렸고 실측으로 잡았다** — `char_length(btrim(message)) > 0` 으로 걸었는데, 인자가 하나인 `btrim(text)` 은 **공백 문자만** 제거한다. 탭·개행은 남아서 `E'\n\t '` 이 통과했다. 서비스의 JS `.trim()` 은 전부 제거하므로 **두 층이 서로 다른 규칙을 쓰고 있었고**, DB 를 최종 방어선이라 부르면서 실제로는 더 헐거웠다. `message ~ '[^[:space:]]'` 로 고쳤다(`20260731060000`). 80자를 코드포인트로 통일한 것과 같은 부류의 실수다 — **두 층의 셈법이 다르면 한쪽만 통과하는 값이 생긴다.**
  남는 차이: JS `.trim()` 은 NBSP(U+00A0) 까지 제거하지만 POSIX `[[:space:]]` 는 아니다. 서비스가 항상 먼저 돌고 더 엄격해서 실사용 경로에서는 드러나지 않는다.
- **`submitGrape` — 슬롯 배정과 재시도가 여기 산다** — 리포지토리 `addGrape` 는 "이 슬롯을 원자적으로 점유하라"는 원시 연산으로 두고, 빈 슬롯 무작위 선택과 `SlotTakenError` 재시도는 서비스가 한다. 방문자는 충돌이 있었다는 사실조차 모른다 (§3 마찰 0).
- **재시도마다 페이지를 다시 읽는다** — 충돌했다는 건 그 사이 판이 바뀌었다는 뜻이라, 낡은 슬롯 목록으로 재시도하면 같은 충돌을 반복한다.
- **슬롯 충돌만 재시도한다** — 주인 차단·길이 초과 등은 다시 시도해도 같은 결과라 즉시 올린다. `withUniqueSlug` 와 같은 구조.
- **`pickEmptySlot` 을 순수 함수 + `random` 주입으로** — 무작위 로직은 주입 없이는 경계를 검증할 수 없다. `() => 0` 과 `() => 0.999` 로 양 끝에서도 찬 슬롯을 고르지 않는지 확인한다.
- **`resolveOrigin` 을 분리** — `/my` 가 `host.startsWith('localhost')` 로 프로토콜을 추론하고 있어서 `127.0.0.1` 이나 `[::1]` 로 접속하면 https 로 오판했다.
- **`getCurrentUser` 가 세션 쿠키 없으면 즉시 null** — `/v/[slug]` 는 링크 공유형이라 미로그인 방문자가 대부분인데, 그 전원이 GoTrue 왕복 + DB 조회를 한 번씩 낭비하고 있었다. 가장 뜨거운 공개 경로다.
- **`getOwner(vineId)` 추가** — `{이름}'s Vine` / `Compliment {이름}` 에 필요. STEP 6 에서 "슬러그를 이름 자리에 끼우면 틀린 값이 남는다"며 비워 뒀던 자리를 채웠다.
- **`getVisitorPage` 의 주석과 코드가 어긋나 있던 것 수정** — 주석은 "404 로 감추지 않는다"인데 코드는 null 을 돌려 404 가 되고 있었다. 코드 쪽 동작(404)이 맞으므로 주석을 사실에 맞췄다.
- **핵심 루프를 실서버 E2E 로 고정** — 판 생성 → 공유 URL → 미로그인 방문자 붙이기 → 판에 반영 → 주인 차단 → 빈 메시지 차단, 그리고 **막힌 시도가 슬롯을 소모하지 않는지**까지. 이게 STEP 7 이 화면을 붙일 토대다.

## STEP 7 — 회색박스 화면 전체

- **모달 열림/닫힘을 URL 이 갖는다** (`?modal=share`, `?grape=10`) — 클라이언트 상태 없이 서버 렌더만으로 동작하고, 링크로 바로 열 수 있고, 뒤로가기가 자연스럽게 맞고, JS 없이도 된다. `useState` 로 열면 이 넷을 전부 따로 구현해야 한다.
- **딤 오버레이 + 패널 구조를 `components/modal.tsx` 한 곳에 고정** — 모달 3개(+Add Grape)가 같은 뼈대를 쓴다. STEP 12~13 은 이 파일에 스타일만 붙이면 된다.
- **`GrapeBoard` 는 숫자를 하나도 정하지 않는다** — 좌표·크기·종횡비가 전부 `slot-layout.ts` 에서 온다 (절대규칙 5). 좌표가 없는 슬롯은 **그리지 않는다** — 임의의 자리에 던져 놓으면 화면은 채워지지만 틀린 배치가 남는다.
- **빈/채움은 임시 텍스트(○/●)와 `data-filled` 로만 구분** — 색·보더·라운드는 디자인 값이라 작업규칙 9(hex 하드코딩 금지)에 걸린다. 회색박스 단계에서 시각 구분이 필요하면 텍스트가 정답이다.
- **`data/steps.ts` 신설 — 이번 범위("app/ components/ 만")를 벗어났다** — PRD §6 이 How It Works 01~05 를 이 파일 소관으로 지정했고 절대규칙 6 이 문구 하드코딩을 금지한다. 컴포넌트에 박는 쪽이 절대규칙 위반이라 파일을 만들었다. 원 크기 `scale` 은 PRD 에 값이 없어 전부 1 + TODO.
- **See Grape 는 채워진 알만 연다** — 빈 슬롯이나 범위 밖 인덱스로 URL 을 조작해도 모달이 뜨지 않는다. 판이 공개라 URL 은 아무나 만질 수 있다.
- **Add Grape 모달은 `cta.kind === 'add'` 일 때만 렌더** — 주인이 `?modal=add` 를 직접 열어도 폼이 없다. 서버가 다시 거절하지만(PRD §7-7), 열리지 않는 편이 낫다.
- ⚠️ **`SlotTakenError` 는 방문자에게 도달하지 않는다** — 요청에 "SlotTakenError 시 안내"가 있었지만, 확정된 설계상 서버가 빈 슬롯을 배정하고 충돌 시 조용히 재시도한다(§3 마찰 0). 사용자가 실제로 만나는 상태는 **`PAGE_FULL`** 이고 그건 화면에 표시된다. 재시도를 없애고 충돌을 노출하면 "다 쓰고 Send 눌렀는데 실패"가 되므로 되돌리지 않았다.
- ⚠️ **마크업 재구성이 기존 라우트 테스트 3개를 깼다** — `/my` 빈 상태에서 displayName 을 뺐고(PRD §5.5 는 버튼 하나만 둔다), 공유 URL 이 모달 안으로 들어갔고, 페이지네이션이 `<p>` → 컴포넌트 `<div>` 로 바뀌었다. 제품 결함이 아니라 테스트가 옛 구조를 보고 있던 것이라 어서션을 새 구조에 맞췄다. 세션 확인은 `data-variant="owner"`(로그인 시에만 렌더)로 바꿔 화면 변경에 덜 취약해졌다.

## STEP 8 — 통합테스트 (v0.1-logic 동결)

- **통합 테스트는 누적 상태 위에서만 드러나는 것을 본다** — 단위 테스트는 각 규칙을 따로 지키는지 보지만, "14번째까지는 아니고 15번째에만 증설"처럼 **순서와 누적**에 걸린 조건은 루프를 관통해야 드러난다. HTTP·세션·라우팅은 `routes.test.ts` 가 실서버로 따로 본다.
- **가입은 `signUp` 과 같은 경로(`admin.createUser` + `ensureProfile`)를 쓴다** — `signUp` 자체는 `cookies()` 를 타서 요청 컨텍스트 밖에서는 못 부른다. 픽스처가 별도 구현이 되지 않도록 실제 함수를 그대로 조합했다.
- **거절 케이스는 "에러가 났다"로 끝내지 않는다** — 슬롯 중복 후 기존 알의 내용·작성자·총 개수가 그대로인지, 주인 차단 후 그 슬롯이 비어 있는지까지 본다. 거절만 확인하면 절반만 검증한 것이다.

### 로직 패스 회고 (STEP 1~8)

1. **같은 규칙을 두 층에 구현하면 셈법이 어긋난다.** 80자를 UTF-16 length 로 셀 뻔했고(→ 코드포인트로 통일), 빈 메시지는 `btrim(text)` 가 탭·개행을 안 지워 DB 가 서비스보다 헐거웠다. 둘 다 **문서를 읽어서가 아니라 실제로 값을 넣어 봐서** 발견했다.
2. **동시성은 "테스트가 통과했다"로 증명되지 않는다.** 동시 요청 테스트는 우연히 직렬화돼도 통과한다. `createVine` 은 실패 트리거를 주입해 롤백을 확인했고, `attach_grape` 는 다른 세션이 잠근 동안 타임아웃하는지 확인했다. 기전을 따로 때려봐야 한다.
3. **제약에 이름을 붙여 둔 것이 나중에 회수됐다.** `grapes` 의 CHECK 4개가 전부 SQLSTATE `23514` 로 와서, 이름이 없었으면 "80자 초과"와 "익명 이름 유출"을 구분할 수 없었다. 규칙을 스키마에 박는 결정이 에러 매핑까지 값을 만들었다.

## STEP 10 — 디자인 토큰

  - ① **보이지만 값을 못 읽는 것**(`--grape-filled`, `--panel`): PNG 라서 노드에 색이 없다. 다만 후보가 파일 안에 있다 — 각각 `#bf00f3`(= `--brand`), `#eae9e3`(= `--text-sub`) 와 같아 보인다. 확인만 받으면 채운다.
  - ② **디자인이 아예 없는 것**(`--grape-empty`): `Other's Vine`(201:777) 2/2 는 채운 알 8개만 그리고 빈 7칸은 배경 사진 그대로다. PRD §5.5 의 "빈 알 = 아웃라인/저채도"에 해당하는 시안이 없다. **읽기의 문제가 아니라 결정의 문제다.**

## STEP 10c — --grape-filled / --panel 확정

- **두 값은 Figma 에서 읽은 게 아니라 확인받은 값이다** — 해당 ellipse 가 PNG 라 노드에 색이 없어서, 파일 안의 다른 노드에서 나온 후보(`#bf00f3`, `#eae9e3`)를 제시하고 승아님이 맞다고 확인해 준 것이다. 주석에 그 사실을 명시했다. 출처가 다르면 나중에 값이 틀렸을 때 어디부터 봐야 하는지가 달라진다.
- **별칭(`var(--brand)`, `var(--text-sub)`)으로 정의했다** — 같은 색이 두 군데 적히면 한쪽만 바뀌어 어긋난다. 브랜드 색이 바뀌면 포도알도 같이 바뀌는 게 맞다. 나중에 갈라져야 한다면 그때 리터럴로 떼어낸다.
- ⏸ **`--grape-empty` 는 여전히 미정** — 시안이 없다. 아웃라인으로 정해지면 색뿐 아니라 **보더 두께도 함께** 필요하다.

## STEP 11 — 폰트 · 에셋

- **에셋이 이미 있었다** — `public/images/` 에 `main_1/2.png`, `myvine_1/2.png` 가, `public/video/` 에 `main.mp4`, `myvine.mp4` 가 들어 있었다. Figma 에서 뽑은 넝쿨 사진은 버리고 승아님 파일을 썼다. `_1` = 시작 프레임, `_2` = 끝 프레임이고, **`main_2.png` 가 곧 "Main 폴백용 마지막 프레임"** 이다(영상 마지막 프레임을 추출해 대조 확인). 중복 파일을 만들지 않았다.
- **Main 배경은 밝고 My Vine 배경은 어둡다** — STEP 10 에서 `--text`(검정) / `--text-on-board`(흰색)로 나눈 판단이 실제 에셋으로 확인됐다. 하나로 뭉쳤으면 한쪽이 사진에 묻혔다.
- **폰트를 서로 다른 방식으로 로드한다** — 일관성보다 실익.
  - Kode Mono: `next/font/local` + `public/fonts/`(10KB 1개). 디자인의 근간이라 **버전을 고정**한다. latin 서브셋만 쓴다 — 이 범위가 U+0000–00FF 를 포함해 é·ñ·ü 까지 덮고, latin-ext 는 이 서비스에 나오지 않는다. **두 서브셋을 같이 등록하면 안 된다** — `next/font/local` 은 unicode-range 를 표현할 수 없어 뒤 파일이 앞을 덮어써 기본 라틴이 통째로 사라진다.
  - IBM Plex Sans KR: `next/font/google`. 한글은 `@font-face` 가 **94개**로 쪼개져 있어 수동 관리가 비현실적이다. 빌드 시 self-host 하면서 unicode-range 를 유지해 실제 쓰인 글자의 서브셋만 받는다. `preload: false` — 한글은 사용자 본문에만 나와 첫 화면 임계 경로가 아니다.
- ⚠️ **폰트 스택에서 generic 키워드의 위치가 결정적이다 (실제로 밟았다).** `--font-mono` 를 `var(--font-kode-mono), var(--font-kr), …` 로 이어 붙였는데, `--font-kode-mono` 가 자기 폴백에 `monospace` 를 갖고 있어 펼치면 **한글 폰트보다 앞에 generic 이 놓였다.** generic 은 그 자리에서 시스템 폰트로 반드시 해결되므로 한글이 IBM Plex Sans KR 에 닿지 못하고 시스템 기본 모노로 샜다. **각 변수에서 generic 을 빼고 `--font-mono` 맨 끝에 한 번만** 뒀다. 검증: 펼친 스택에서 `IBM Plex Sans KR`(34) 이 첫 generic(92) 보다 앞. 한글 음절 영역을 덮는 `@font-face` 84개 확인.
- **파비콘은 토큰에서 파생했다** — 피그마에 시안이 없어 `--bg` 위에 `--brand` 원 하나. 새로 디자인한 게 아니라 확정된 값의 조합이다. 시안이 나오면 교체.
- **OG 는 `main_2.png`(넝쿨이 자란 상태)에서 1200×630 크롭** — 브랜드 인상이 있는 프레임을 골랐다.
- ⚠️ **`metadataBase` 는 빌드 시점에 박힌다** — `/` 가 정적 프리렌더라 `next start` 에만 `SITE_URL` 을 주면 반영되지 않는다. 빌드 환경에 설정해야 하고, Vercel 은 `VERCEL_URL` 을 빌드 때 자동으로 준다. 없으면 OG 이미지가 localhost 를 가리켜 공유 시 404 가 된다.
- **테스트 실행 전 dev/preview 서버를 반드시 내릴 것** — 라우트 테스트가 `next build` 를 돌리는데 다른 서버가 `.next` 를 잡고 있으면 충돌해 실패한다. 실제로 한 번 밟았고 제품 문제가 아니었다.

### How It Works (201:682)

- **포도색이 두 가지다** — 밝은 마젠타(`--brand`)와 **짙은 포도색 `#60007b`**(`--grape-deep` 신규). 원과 그 위 번호 뱃지가 **서로 반대 색**이다. 문구 색도 원을 따라 갈린다(마젠타 원 위엔 검정, 진보라 원 위엔 `--text-sub`).
- **모든 단계가 서로 다른 각도로 기울어 있다** — 01 `32.96°` / 02 `-15.75°` / 03 `11.56°` / 04 `-18.67°` / 05 `16.43°`, 장식은 `20.95°` / `-15°`. 원·뱃지·문구는 Figma 에서 각각 독립 노드라 따로 배치하고 같은 각도를 준다.
- **크기는 단조 감소가 아니라 교대다** — 원 485 / 275 / 367 / 197 / 275, 글자 47.6 / 23.0 / 38.3 / 15.6 / 28.9. 마젠타 단계(01·03·05)가 크고 진보라 단계(02·04)가 작다. PRD §5.3 의 "점점 줄여가며"는 대략적인 서술이고 실제로는 큰 것과 작은 것이 번갈아 온다.
- ⚠️ **원 크기 스케일 값을 페이지에 뒀다** — PRD §6 은 `data/steps.ts` 소관이라고 하지만 그 파일의 `scale` 은 전부 1(TODO)이고 data/ 가 이번 범위 밖이다. data/ 수정이 열리면 옮겨야 한다.
- **문구는 오른쪽 정렬** — 각 줄이 상자의 오른쪽 끝에 붙는다. 그래서 첫 줄이 짧아야 왼쪽의 번호 뱃지를 비켜 간다.

#### 시안과 다른 점 (값 필요)

- **문구 줄바꿈이 달라 뱃지를 덮는다** — Figma 는 손으로 끊어 놨다(예: 03 은 `Waiting ` / `for friends'` / `compliments`). `data/steps.ts` 는 한 줄짜리 문자열이라 폭만으로는 재현되지 않고, 첫 줄이 길어지면서 오른쪽 정렬 때문에 왼쪽으로 밀려 뱃지와 겹친다. **개행 위치가 data/ 에 있어야 풀린다.**

## STEP 12b — data/ 정리 (조판을 데이터로)

번역 중 네 화면에서 같은 문제가 반복됐다: **Figma 가 손으로 끊어 놓은 줄을 폭만으로 재현할 수 없다.** 브라우저 글자 폭이 Figma 와 미세하게 달라 늘 한 낱말씩 어긋나고, How It Works 는 오른쪽 정렬이라 첫 줄이 길어지면 번호 뱃지를 덮었다. **조판이 곧 디자인이므로 끊는 위치를 데이터에 둔다.**

- **`copy.ts` 에 `tagline` 과 `headline` 을 분리했다** — 태그라인(PRD §1)은 문장이라 마침표가 있고, 화면 헤드라인(Figma 201:654 / 201:681)은 표제라 없다. 하나로 쓰면 어느 한쪽이 틀린다. 비주얼 SSOT 는 Figma 다(PRD §12).
- **줄 배열을 원본으로, 한 줄 문자열을 파생으로** — `MAIN_SUBTITLE_LINES` / `ABOUT_BODY_LINES` / `step.lines` 를 두고 `join(' ')` 으로 `subtitle` / `body` / `text` 를 만든다. 두 벌을 각각 적으면 한쪽만 고쳐져 어긋난다.
- **`copy.about.note`(`is...`) 추가** — 헤드라인 오른쪽의 작은 장식 문구(201:680). 컴포넌트에 박으면 절대규칙 6 위반이라 비워 뒀던 자리다.
- **`about.title` 이 이제 헤드라인이다** — STEP 7 에서 `'About'` 로 뒀던 자리표시자를 실제 값(태그라인)으로 교체했다.
- **`steps.ts` 의 `scale` 필드를 제거했다** — PRD §6 은 "원 크기 스케일 값"을 이 파일 소관이라고 했지만, 실측하니 원과 글자가 **서로 다른 비율**로 줄어든다(원 1/.567/.757/.406/.567 vs 글자 1/.483/.805/.327/.606). 스칼라 하나로 표현되지 않아 두는 것 자체가 거짓말이 된다. 크기·좌표·각도는 화면 쪽 비주얼 표에 함께 뒀다 — 흩어 놓는 것보다 고치기 쉽다.
- **`04` 는 "A Friend" 로 F 가 대문자다** — PRD §5.3 은 소문자인데 Figma 가 대문자다. 비주얼 SSOT 를 따랐다.

- **`--pill-current-opacity` 를 `--dim-opacity` 로 통합** — 현재 화면 pill 과 placeholder 가 같은 30% 다. 이름이 둘이면 한쪽만 바뀌어 어긋난다.
- **타이틀 `Log In` 과 버튼 `Log in` 은 다른 문구다** — I 의 대소문자가 다르다(201:731 vs 201:737). `copy.auth.logInTitle` 을 따로 뒀다.
- ⚠️ **Sign Up 프레임이 Figma 에 없다** — Login 구조를 그대로 쓰고 displayName 필드를 하나 더했다. 시안이 나오면 교체할 것.

#### ⚠️ `--panel` 값이 틀렸다 (수정 필요)

Login 배경은 `#eae9e3`(201:716 프레임 fill, 코드에서 읽음)이고, 그 위에 패널(523)과 배경 원 6개가 **눈에 보이게 더 밝다**. 그런데 지금 `--panel` 은 `#eae9e3` — 배경과 같은 값이라 **렌더에서 통째로 사라진다.**

STEP 10c 에서 `--panel = #eae9e3` 로 확정한 근거는 "모달 패널이 CTA 버튼 배경과 같아 보인다"였는데, 그 모달은 **어두운 사진 위 딤** 위에 있어서 같은 값으로도 밝게 읽혔다. 평평한 `#eae9e3` 위에서는 성립하지 않는다.

Ellipse 가 PNG 라 값을 읽을 수 없고 픽셀 샘플링은 작업규칙 8 위반이다. **패널 색을 값으로 받아야 한다.**

시안에서 라디오가 **선택된 상태**로 그려져 있어 1번일 가능성이 높지만, 추측하지 않고 확인을 기다린다.

## STEP 12c — 미정 정리

### 해결: Add Grape 이름 입력

추측이 필요 없었다 — **PRD §5.10 에 답이 있다**: *"익명 미선택 시 이름 입력 필요."*
Figma 201:904 에 필드가 안 보이는 이유는 그 프레임이 **Unknown 이 켜진 상태**를 그렸기 때문이다(201:949 라디오가 채워져 있다). 익명이면 이름을 받을 이유가 없으므로 시안과 모순이 아니다.

- **토글은 CSS 로만** — `.form:has(.radio:checked) .authorName { display: none }`. 이 폼은 서버 렌더만으로 동작해야 해서 JS 를 쓰지 않는다.
- **`required` 를 걸지 않는다** — 숨겨진 채 `required` 면 브라우저가 전송을 막으면서 포커스할 곳이 없어 아무 안내도 못 준다. 이름 누락은 서버가 `InvalidAuthorNameError` 로 거른다.
- **기본값은 꺼짐**(기명) — PRD 가 "익명 **미**선택 시"를 기본 흐름처럼 서술한다. Figma 는 켜진 상태를 예시로 그린 것.
- 검증: 기명(이름 있음) 통과 / 익명(이름 빈칸) 통과 / 기명인데 이름 빈칸 → `error=INVALID_AUTHOR_NAME`. CSS 토글은 실제 브라우저에서 `display` 가 바뀌는 것을 확인했다.

### 확인: Sign Up 화면

Figma 에 프레임이 없다. Login(201:716) 구조에 `displayName` 필드를 더해 만들었다. 입력 세 개는 STEP 4 에서 확정된 것이라 임의 추가가 아니다. 시안이 나오면 교체한다.

### ⏸ 남은 미정 — 값이 있어야 진행 가능

두 건 다 **Figma 에서 읽을 수 없는 색**이고, 이미지 픽셀 샘플링은 작업규칙 8(측정 스크립트 금지)에 걸린다.

1. **Login·Sign Up 의 패널/배경 원 색**
   Login 배경은 `#eae9e3`(201:716 프레임 fill, 코드로 확인)인데 그 위 패널(523)과 배경 원 6개가 눈에 보이게 더 밝다. 지금 `--panel` 이 `#eae9e3` 라 **그 화면에서만 통째로 사라진다.**
   모달 딤 위에서는 `#eae9e3` 가 제대로 읽히므로(실측 확인), 값이 틀린 게 아니라 **Login 계열에 다른 값이 하나 더 필요**한 것으로 보인다.

2. **빈 포도알 (`--grape-empty`)**
   Figma 의 어느 판도 빈 슬롯을 그리지 않는다. PRD §5.5 는 "빈 알 = 아웃라인/저채도"라고 하므로 **시안 자체가 없다.** 아웃라인이면 색과 보더 두께가 함께 필요하다.

나머지 화면은 시안과 일치한다. 위 두 값 없이도 STEP 13(폴리시)의 다른 항목은 진행할 수 있지만, 이 둘이 채워지기 전에는 `v0.2-visual` 을 동결할 수 없다.

## STEP 13 — 폴리시 + 전체 기능 점검 (v0.2-visual)

### 미정 두 값을 채웠다 — 새 hex 를 지어내지 않고 파생시켰다

- **`--panel-on-surface`** — Login·Sign Up 의 패널과 배경 원. 시안에서 바탕(`#eae9e3`)보다 밝게 보인다는 사실만 확인됐고 값은 PNG 라 읽을 수 없다. 새 색 대신 `color-mix(in srgb, var(--surface) 88%, #fff)` 로 뒀다 — **확정된 값에 앵커돼 있어** 정확한 값을 받으면 한 줄만 바꾸면 된다.
- **`--grape-empty`** — Figma 에 시안이 없다. 색을 지어내는 대신 **이미 있는 디자인 언어를 적용**했다. 이 서비스의 아웃라인은 전부 "채움 없음 + 2px 보더"(사이드바 pill 201:647)이므로 빈 알도 같은 규칙, 색은 포도알 색.

### 코드 점검에서 찾아 고친 결함 4건

1. ⚠️ **로그아웃이 모든 기기의 세션을 끊었다.** Supabase `signOut()` 기본 `scope` 가 `'global'` 이라 그 계정의 **모든 세션**이 죽는다 — 노트북에서 로그아웃하면 폰에서도 로그아웃된다. 기기 두 대를 흉내내 재현하고 `scope: 'local'` 로 고쳤다. **전체 점검을 안 돌렸으면 못 찾았을 결함이다** (처음엔 "주인 차단 실패"로 보였는데, 파 보니 앞선 로그아웃이 세션을 죽여서 주인 판정이 성립하지 않았던 것).
2. **Setting 의 `My Account >` 가 죽은 링크였다.** `?modal=account` 를 걸어 놓고 핸들러가 없었다.
3. **로그아웃할 방법이 화면 어디에도 없었다.** STEP 12 에서 `/my` 를 시안대로 다시 그리면서 회색박스의 로그아웃 버튼이 사라졌다. 2번과 함께 **My Account 모달**로 해결했다 — Figma 에 프레임이 없지만 계정 화면이 로그아웃의 제자리이고, 죽은 링크와 탈출구 없음을 동시에 푼다.
4. **모달이 열려도 좌상단이 페이지네이션이었다.** Figma 의 모달 프레임(201:791 / 823 / 904 / 979)은 모두 `<` 를 그린다. 딤 말고 닫는 길이 하나 더 있어야 한다.

### 접근성 — 시안에 없지만 없으면 못 쓰는 것들

- **포커스 표시가 아예 없었다.** 키보드로는 지금 어디 있는지 알 방법이 없었다. 판을 채우는 게 이 서비스의 전부인데 빈 알 사이를 탭으로 옮겨다닐 수 없다. 새 색을 만들지 않고 `--link` 파랑으로 `:focus-visible` 을 그린다.

- hover 상태가 없어 pill 이 그냥 라벨처럼 보였다. 새 색 없이 현재 색을 채움으로 뒤집는다.

## STEP 14 준비 — 스크럽 영상 재인코딩

연출로 넘어가기 전에 영상을 실측했더니 **스크럽이 성립하지 않는 상태**였다.

### 원인은 용량이 아니라 키프레임이었다

26MB 라는 숫자가 눈에 띄지만 진짜 문제는 **I-frame 이 전체 121프레임 중 1번 하나**뿐이었다는 것이다. 브라우저는 `currentTime` 이 바뀌면 **직전 키프레임으로 점프한 뒤 거기서부터 디코딩**한다. 키프레임이 1번뿐이면 **어느 지점으로 스크럽하든 항상 1번부터** 최대 120프레임을 다시 푼다 — 그것도 4060×2040(828만 화소)으로.

### 실측 (Chrome, 60개 지점을 실제로 seek)

| | 중앙값 | p95 |
|---|---:|---:|
| 원본 4060×2040 | **141.9ms** | 257.2ms |
| 재인코딩 1440 | **2.8ms** | 4.0ms |

60fps 예산은 프레임당 16.7ms 다. 원본은 **예산의 8.5배** — 초당 7프레임이라 끊기는 정도가 아니라 스크럽 자체가 안 된다. 재인코딩본은 예산의 17%.

**50.7배.** 해상도 축소는 거들었을 뿐이고 결정적인 건 `-g 1` 이다.

### 적용

`-vf scale=1440:-2 -c:v libx264 -crf 20 -g 1 -keyint_min 1 -sc_threshold 0 -profile:v high -pix_fmt yuv420p -movflags +faststart -an`

| | 전 | 후 |
|---|---:|---:|
| main.mp4 | 7.0MB | **2.8MB** |
| myvine.mp4 | 26.4MB | **7.8MB** |
| 해상도 | 4060×2040 | 1440×724 (비율 유지) |
| 키프레임 | 1 | **121 (전 프레임)** |

- **CRF 20** — 예산이 15MB 인데 최고 품질이 7.8MB 로 들어와서 화질을 깎을 이유가 없었다 (24→5.1MB / 28→3.2MB / 32→2.0MB 도 재봤다).
- **`faststart`** — moov 를 파일 앞에 둔다. 다 받기 전에 스크럽이 시작된다.
- **`-an`** — 스크럽 영상에 소리는 안 쓴다.
- 길이·fps·프레임수(5.04s / 24 / 121)는 손대지 않았다.
- iOS: `h264 High / yuv420p` 확인.

⚠️ 측정은 이 맥의 헤드리스 Chrome 이다. 실제 iOS 는 절대 수치가 더 느리다. 다만 "1번 프레임부터 다시 푼다"는 원인은 기기와 무관하므로 상대 차이는 유지된다.

⚠️ 원본 33.5MB 는 **git 히스토리에 그대로 남는다**(`.git` 44MB, public 레포). 히스토리 재작성은 force push 라 별도 판단 사항으로 남긴다.

## STEP 14 — 스크롤 하네스 (연출 패스 시작)

연출 패스의 바닥. 진행률을 **만들어 나눠 주기만** 한다. 그걸로 영상을 스크럽하는 건 STEP 15, 오버레이를 구간에 매핑하는 건 STEP 16 이다 (작업규칙 4 — STEP 하나 = 연출 하나).

### 진행률을 두 갈래로 내보낸다

| 갈래 | 쓰는 곳 |
|---|---|
| CSS 변수 `--scroll-progress` (씬에 얹음, 상속) | STEP 16 오버레이 — JS 없이 `var()` 로 읽는다 |
| `subscribe()` 구독 | STEP 15 영상 — `currentTime` 은 숫자가 필요하다 |

**둘 다 React state 를 쓰지 않는다.** 진행률은 초당 60번 바뀌는데 state 에 담으면 그때마다 트리 전체가 다시 그려진다. ref 에 담고 직접 통지한다. 그래서 진행률 인디케이터는 **JS 가 한 줄도 없고**(CSS 변수만 읽는다) 서버 컴포넌트로 남는다.

### lerp 를 하네스에 뒀다

절대규칙 10 은 `currentTime` 을 항상 lerp 로 접근하라고 한다. 소비자마다 lerp 를 하게 두면 **한 곳만 잊어도 규칙이 깨지고, 깨진 걸 눈으로만 알 수 있다.** 하네스가 이미 부드러워진 값만 내보내면 소비자는 잊을 수가 없다 — 규칙을 문서가 아니라 구조로 지킨다.

수학적으로 지수 감쇠는 목표에 영원히 도달하지 않으므로 **충분히 가까워지면 스냅**한다. 안 하면 영상이 마지막 프레임에 영영 못 닿고 매 프레임 의미 없는 갱신이 계속된다.

### 계산은 순수 함수로 떼어 냈다 (`lib/scroll-math.ts`)

rAF 루프 안에 섞여 있으면 눈으로 굴려 보는 것 말고는 검증할 방법이 없다. 경계(시작·끝·범위 밖·0 나누기·NaN)와 수렴을 단위테스트 13개로 못 박았다. `NaN` 을 0 으로 자르는 건 진행률이 `NaN` 이면 `currentTime` 대입이 통째로 죽기 때문이다.

### reduce 폴백은 CSS 가 먼저 (PRD §9.4)

JS(`useReducedMotion`)도 같은 판단을 하지만 그건 마운트 뒤다. 첫 페인트에 4배 높이가 잠깐이라도 잡히면 스크롤바가 튄다. **CSS 미디어쿼리가 스크롤 구간을 먼저 걷어내고**, JS 는 뒤따라와 Lenis 와 rAF 만 끈다.

### 씬 길이 4배

영상이 5.04초다. 4배면 한 화면 스크롤에 약 1.26초. ⚠️ **Figma 에도 PRD 에도 근거가 없는 값이다.** 스크롤 "감각"의 문제라 눈으로 보고 정해야 한다. 지어낸 값이 아니라 **정해야 하는 값**이라 `data/scroll-cues.ts` 한 줄로 빼 뒀다 (절대규칙 6).

## STEP 15 — Main 스크럽

하네스가 내보내는 진행률을 `video.currentTime` 으로 옮긴다. 그게 전부다.

### lerp 를 여기서 다시 걸지 않는다

절대규칙 10 은 `currentTime` 을 lerp 로 접근하라고 한다. **하네스가 이미 부드러워진 값만 내보내므로 이 대입 자체가 lerp 접근이다.** 소비자 쪽에서 한 번 더 걸면 이중 감쇠라 스크롤을 멈춘 뒤에도 한참 따라온다. STEP 14 에서 lerp 를 하네스에 둔 결정이 여기서 값을 한다.

### seek 를 합친다

진행률은 매 프레임 바뀐다. 앞 seek 가 안 끝났는데 또 대입하면 큐가 쌓여 **스크롤을 멈춘 뒤에도 영상이 계속 움직인다.** 진행 중이면 최신 값만 남겨 뒀다가 `seeked` 에서 이어 간다. 같은 프레임이면 아예 건드리지 않는다(1/48초 이내). 실측 drift 0.

### 끝에서 `duration` 을 그대로 쓰지 않는다

`currentTime = duration` 은 EOF 라 브라우저에 따라 **마지막 프레임을 안 그린다.** 한 프레임 안쪽(`duration - 1/24`)으로 물려 확실히 그 프레임에 앉힌다. 실측 4.9884 / 마지막 프레임 시작 5.0.

### 포스터는 **첫** 프레임 (`main_0.png`, 영상에서 추출)

배경 스틸 `main_2.png` 는 마지막 프레임이라 reduce 폴백으로는 맞지만 포스터로 쓰면 **로드 직후 완성된 넝쿨이 빈 화면으로 튄다.** 영상의 0번 프레임을 그대로 뽑아 포스터로 뒀다 — 지어낸 이미지가 아니라 소스에서 추출한 것이다.

### ⚠️ reduce 인데 mp4 를 받고 있었다 (2단계로 밟았다)

1. **`src` 가 마크업에 있었다.** 서버는 reduce 여부를 알 수 없어 `useReducedMotion` 이 false 를 주고, 그 HTML 이 그대로 나가 브라우저가 파싱하면서 곧바로 받기 시작한다. 하이드레이션 뒤 엘리먼트를 지워도 늦다. → `src` 를 effect 에서 붙이도록 옮겼다.
2. **그래도 1건이 남았다.** `useSyncExternalStore` 는 하이드레이션 중 **일부러 서버 값(false)** 을 돌려준다 — 마크업이 어긋나지 않으려면 그래야 한다. 진짜 값으로 다시 그리는 건 그다음이고, **effect 는 그 사이에 이미 한 번 돈다.** → effect 시점에 `matchMedia` 를 직접 한 번 더 읽는다. 중복이 아니라 **다른 시점의 값**이다.

reduce 를 켠 사람에게 2.8MB 를 떠넘기는 일이었다. 요청 수를 세지 않았으면 "엘리먼트가 없으니 됐다"로 넘어갔을 결함이다.

CSS 에도 `display:none` 을 둔다 — JS 가 지우는 건 하이드레이션 뒤라, 그때까지 포스터(빈 크림색)가 보이다가 배경 스틸(완성된 넝쿨)로 튄다.

## STEP 16 — Main 오버레이

PRD §5.1 의 시퀀스를 진행률 구간에 매핑했다. 넝쿨이 뻗어나감 → 후반부 포도알이 하나씩 → 마지막에 타이틀·서브카피·사이드바.

### 전부 CSS 다. JS 가 한 줄도 없다

PRD §9.1 이 "오버레이는 영상에 인코딩하지 않고 **DOM 레이어**를 진행률 구간에 매핑"하라고 한 그대로다 — 문구를 고치려고 영상을 다시 뽑는 일이 없어야 한다.

하네스가 씬에 얹은 `--scroll-progress` 와 요소에 붙은 구간으로 CSS 가 직접 계산한다:

```css
opacity: clamp(0, calc((var(--scroll-progress) - var(--cue-from)) / (var(--cue-to) - var(--cue-from))), 1);
```

리렌더도, 클라이언트 컴포넌트도 없다. **Main 은 여전히 서버 컴포넌트고 정적 프리렌더된다.** STEP 14 에서 진행률을 CSS 변수로도 내보낸 결정이 여기서 값을 한다.

### 기본값이 "보임"이다

`var(--scroll-progress, 1)` — 씬 밖에서 `.reveal` 을 쓰면 감춰지는 게 아니라 **보인다.** 실수의 결과가 "안 보임"이면 안 된다. 대신 씬은 서버 렌더에서 `--scroll-progress: 0` 을 박아 둔다. 안 그러면 하이드레이션 전까지 다 보였다가 사라진다.

### JS 가 없으면 영영 안 보인다 — `scripting: none` 으로 받는다

서버에 0 을 박아 두면 JS 가 아예 없는 환경에서 진행률이 영영 0 이라 **타이틀도 사이드바도 영원히 안 보인다.** 스크롤 연출을 못 볼 뿐이지 내용을 못 볼 이유는 없다. `@media (scripting: none)` 으로 전부 드러낸다. 이 프로젝트가 모달을 URL 로 연 것과 같은 이유다.

### 공용 컴포넌트에 연출을 밀어 넣지 않았다

`Sidebar` 는 다섯 화면이, `DecorGrapes` 는 네 화면이 쓴다. Sidebar 는 Main 에서 **감싸는 쪽**을 택했다(`.sidebar` 가 absolute 인데 감싸는 div 는 정적이라 위치 기준이 그대로다). DecorGrapes 는 알마다 구간이 달라야 해서 감쌀 수 없으므로 **선택 prop** 으로 뒀다 — 안 넘기면 그냥 다 보인다.

### 구간 값

앞 절반(0~0.5)은 넝쿨만 자란다. 오버레이가 일찍 끼면 영상 자체를 못 본다. 포도알 0.5→0.8 (0.1씩 하나씩), 타이틀 0.82→0.9, 서브카피 0.86→0.94, 사이드바 0.9→0.98.

⚠️ PRD 가 정한 건 **순서와 대략의 자리**("후반부", "마지막")뿐이고 Figma 에 타이밍 시안이 없다. 숫자는 그걸 구간으로 옮긴 것이라 `MAIN_SCENE.length` 와 같은 성격 — `data/scroll-cues.ts` 에서만 고친다 (절대규칙 6).

## STEP 17 — My Vine 생성 리빌

`Create My Vine` 을 누르면 넝쿨이 **스톱모션처럼 뚝뚝 끊기며** 드러나고, 끝나면 그때 폼이 전송돼 빈 포도판으로 넘어간다 (PRD §9.2).

### ⚠️ 여기서는 `currentTime` 을 lerp 로 접근하지 않는다 — 절대규칙 10 과 충돌한다

절대규칙 10 은 *"항상 lerp, 직접 대입 금지"* 다. 그런데 그 규칙의 근거는 PRD §9.1 의 **"안 하면 계단처럼 튐"** 이고, **이 화면에서는 계단이 목적이다.** PRD §9.2 가 이 연출에 대해서만 `Math.floor(t * steps) / steps` 로 양자화하라고 따로 지정했고, lerp 를 걸면 계단이 뭉개져 연출 자체가 사라진다.

**규칙을 어긴 게 아니라 규칙이 겨냥한 상황(스크럽)이 아니라고 판단했다.** Main 은 그대로 하네스의 lerp 를 쓴다. 이 판단이 틀렸다면 되돌릴 곳은 `create-vine-reveal.tsx` 의 `tick` 하나다.

### 전송을 막지 않고 **미룬다**

리빌이 끝나면 `form.submit()` 으로 네이티브 전송을 그대로 태운다. fetch 로 바꾸면 서버 리다이렉트·에러 처리 경로를 전부 새로 만들어야 하고, 그건 연출 패스가 로직을 건드리는 일이다 (작업규칙 4).

덕분에 **JS 가 없으면 지금 그대로 즉시 전송된다** — `onSubmit` 이 안 걸릴 뿐이다. reduce 도 즉시 전송한다 (PRD §9.4, 실측 814ms).

### 영상이 안 오면 기다리지 않는다

`readyTimeoutMs: 1500` — 준비가 안 되면 리빌을 건너뛰고 바로 전송한다. **장식 때문에 판 만들기가 막히면 안 된다.** 로드 실패(`error`)도 같은 길로 빠진다.

미리 받아 두는 건 이 화면에서 할 수 있는 일이 이 버튼 하나뿐이라서다. 누른 뒤에 받기 시작하면 7.8MB 를 빈 화면으로 기다리게 된다. reduce 면 아예 안 받는다(실측 0건) — STEP 15 와 같은 이유로 `src` 를 마크업이 아니라 effect 에서 붙이고, 거기서 `matchMedia` 를 직접 읽는다.

### 그림이 이어 붙는다

`myvine.mp4` 첫 프레임 = 풀밭 = 빈 상태 배경(`myvine_1.png`), 마지막 프레임 = 넝쿨 = 판 배경(`myvine_2.png`). 프레임을 뽑아 눈으로 확인했다. 영상이 나타나는 순간에도, 끝나고 판으로 넘어가는 순간에도 튀지 않는다.

### 검증 — 실제 Chrome 12/12

400프레임을 샘플링해 `currentTime` 의 **서로 다른 값이 정확히 10개**임을 확인했다:

## STEP 18 — 붙이기 낙하

`Send` 성공 → 그 알이 위에서 톡 떨어져 붙는다 (PRD §9.3). 기획 원문: *"실제 스티커판에 한 알을 채워 넣는 감각을 그대로 옮겼다."*

### ⚠️ 연출 패스인데 로직 파일 한 줄을 건드렸다

`/api/v/[slug]/grape` 의 리다이렉트에 `&dropped=<슬롯번호>` 를 붙였다. 작업규칙 4 는 연출 패스에서 로직 수정을 금지한다. **그럼에도 이렇게 한 이유:**

**어느 슬롯이 배정됐는지는 서버만 안다.** 슬롯은 방문자가 고르지 않고 서버가 빈 칸 중에서 뽑아 충돌하면 조용히 다시 시도한다(확정된 설계 · §3 "방문자 마찰 0"). 클라이언트에서 **전후 판을 비교해 새 알을 찾는** 방법도 있고 그러면 로직을 아예 안 건드린다. 하지만 이 서비스는 **여러 방문자가 동시에 붙이는 것이 전제**다(절대규칙 1이 통째로 그 얘기다). 그 사이 남이 붙인 알을 자기 것으로 착각해 **엉뚱한 알이 떨어진다.**

동작은 아무것도 바뀌지 않는다 — 순수한 연출 힌트다. 되돌릴 곳은 리다이렉트 한 줄이다.

### 파라미터는 애니메이션이 끝나면 지운다

`?dropped=` 은 **한 번 떨어뜨리라는 신호**지 화면 상태가 아니다. 남겨 두면 (1) 방문자가 주소를 복사해 갈 때 따라가고 (2) 새로고침할 때마다 같은 알이 다시 떨어진다. `history.replaceState` 라 서버 왕복도 히스토리 항목도 안 늘어난다.

지울 때 주소를 **그 시점에 다시 읽는다.** effect 시점의 주소를 붙들고 있으면 그 사이 모달을 열었을 때 옛 주소로 되돌린다.

### duration / curve — PRD 가 "STEP 에서 정확한 값으로" 남겨 둔 자리

- **420ms** — "톡"이다. 300 이하는 무슨 일이 있었는지 못 보고, 600 을 넘으면 떨어지는 게 아니라 내려앉는다.
- **지름 3배 높이** — `translate` 의 %는 자기 자신 크기 기준이고 알은 정사각이라 `300%` 가 곧 지름 3개다. 화면이 커져도 낙하 거리의 인상이 유지된다.
- **곡선 두 구간** — 떨어질 때 `cubic-bezier(0.45, 0, 0.9, 0.45)` 가속(중력). 등속이면 매달려 내려오는 것처럼 보인다. 닿은 뒤 `cubic-bezier(0.2, 0.9, 0.3, 1)` 감속으로 눌린 모양(`scale(1.12, 0.88)`)이 되돌아온다.
- **`transform-origin: 50% 100%`** — 눌릴 때 **바닥을 딛는다.** 가운데 기준이면 위아래로 같이 줄어 붙는 게 아니라 작아지는 것처럼 보인다.

곡선은 값이 아니라 모양이라 CSS 에 두고, 시간·거리만 `data/scroll-cues.ts` 에 뒀다.

빈 칸은 절대 떨어지지 않는다 — 주소는 누구나 고칠 수 있으므로 `filled && slotIndex === dropSlot` 로 이중 확인한다.

### 검증 — 실제 Chrome 12/12
