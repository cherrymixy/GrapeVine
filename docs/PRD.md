# 포도나무열렸네 (GRAPEVINE) — MVP PRD

> 친구가 남긴 **이름 + 칭찬 한마디**가 내 포도송이의 빈 알을 하나씩 채우는, **링크 공유형 칭찬 수집 웹앱.**
> 판이 꽉 차면 **다음 페이지가 자동으로 열린다.** Next.js + TypeScript.
> 태그라인: **"Grapes are growing on the vine."**

---

## 0. 작업 방식 (하네스 엔지니어링)

1. **로직 먼저 수렴.** 판/페이지/포도알/공유링크·핵심 규칙을 UI와 분리해 *먼저 동결*. 슬롯 좌표·문구는 `data/`로 외부화.
2. **디자인은 두 층.** (a) 토큰·셸은 초반에, (b) 화면별 비주얼은 로직 동결 후.
3. **연출은 별도 3패스.** 이 프로덕트의 핵심 가치가 모션이므로 디자인 패스와 분리해 **독립 패스**로 굴린다. (스크롤 하네스 → 스크럽 영상 → 리빌)
4. **빌드는 복붙 단계별 프롬프트로** 쪼갠다. 규칙은 `CLAUDE.md`에 영속화.
5. **한 번에 하나 → 결과 확인 → 다음.** 묶지 않는다.
6. **시각 조정은 모호한 말 금지.** 판단은 사람이, 도구엔 정확한 스펙으로. 측정 스크립트 금지.
7. **핸드오프 정밀도 사다리:** 말 → 값(px/hex/ms) → 이미지 → **Figma MCP `get_design_context`(구조화 비주얼 스펙)**. 막히면 한 단계 올린다.
8. **비주얼 SSOT는 Figma MCP.** 피그마 노드를 직접 읽어 토큰 기반 컴포넌트로 '번역'. Figma가 막히면 Codex HTML/CSS로 폴백.

## 1. 개요

- **한 줄 정의:** 링크를 받은 친구가 로그인 없이 빈 포도알에 칭찬을 붙이고, 판이 꽉 차면 새 페이지가 열리는 칭찬 수집 웹앱.
- **핵심 루프:** 판 만들기(Create) → 링크 공유(Share) → 친구가 붙이기(Add) → 주인이 열람(See).
- **왜:** 칭찬은 받는 순간 분명히 기분이 좋지만 일상에서 누군가 작정하고 건네는 일은 드물다. 생일 롤링페이퍼처럼 **'판'이 깔리면** 사람들은 비로소 한 마디씩 마음을 보태기 쉬워진다. 누구나 아는 '포도알 칭찬 스티커판'을 그대로 인터페이스로 옮긴다.
- **차별점:** 기능이 아니라 **연출**. 스크롤에 따라 넝쿨이 자라는 랜딩과, 판 생성 시 넝쿨이 드러나는 리빌이 이 서비스의 실질적 제품이다.

## 2. 목표 & 비목표 (MVP)

**포함**
- 주인 회원가입/로그인 **(최소)**.
- **판 생성**: 옵션 없음. 버튼 하나로 기본 포도판 1개 생성 + 리빌 연출.
- **페이지 자동 증설**: 마지막 페이지가 꽉 차면 다음 페이지 자동 생성, `1/2 >` 페이지네이션으로 이동.
- **링크 공유**: 슬러그 URL + Copy.
- **방문자 칭찬 작성**: 로그인 불필요. 이름(또는 Unknown 익명) + 칭찬 한마디 → 빈 알에 붙임.
- **열람**: 채워진 알 클릭 → 작성자명 + 칭찬 내용.
- **랜딩 3종**: Main(스크롤 스크럽 영상), About, How It Works.
- Setting(My Account 최소).

**비목표 (부록 D)**
- 포도판 생성 옵션(송이 크기 / 테마 / 스킨 선택) — **삭제 확정**
- QR 공유 — **삭제 확정**
- 완성 축하 화면 / 캡처·공유 — **삭제 확정**
- 새 칭찬 알림 — **삭제 확정**
- 채운 비율에 따라 익어가는 색 변화 — **삭제 확정**
- 칭찬 랭킹, 포도밭 둘러보기, 친구/팔로우, 댓글, 다국어, 이미지 첨부

> 위 5개는 초기 기획에 있었으나 **의도적으로 제거**했다. 기능을 덜어내고 연출에 집중하는 것이 이 MVP의 방향이다. AI가 "있으면 좋을 것 같아서" 되살리지 않도록 `CLAUDE.md`에 비목표로 명시한다.

|---|---|---|

## 5. 화면 정의

### 5.0 라우트 & 표현 방식

피그마 프레임 구조 기준. `Rectangle 26`(딤 오버레이)가 깔린 프레임은 **모달**, 없는 프레임은 **별도 페이지**.

| 화면 | 라우트 | 형태 | 인증 | GNB |
|---|---|---|---|---|
| Main | `/` | 페이지 (스크롤 스크럽) | X | About / How It Works / Login |
| About | `/about` | 페이지 | X | 동일 |
| How It Works | `/how-it-works` | 페이지 | X | 동일 |
| Login / Sign Up | `/login`, `/signup` | 페이지 (원형 패널) | X | 동일 |
| My Vine | `/my` | 페이지 | **O** | My Vine / Share My Vine / Setting |
| Share My Vine | `/my` 위 모달 | **모달** | O | 동일 |
| Setting | `/my` 위 모달 | **모달** | O | 동일 |
| See Grape | `/my` 위 모달 | **모달** | O | 동일 |
| Other's Vine | `/v/{slug}` | 페이지 | X | `{이름}'s Vine` 단일 |
| Add Grape | `/v/{slug}` 위 모달 | **모달** | X | 동일 |

공통 셸: **우상단 세로 스택 사이드바**(라운드 아웃라인 pill 3개), **좌상단 뒤로가기 `<` 또는 페이지네이션 `1/2 >`**.

### 5.1 Main (`/`)
- **긴 스크롤 영역 + 고정(pin) 영상 1개.** 스크롤 진행률 → `video.currentTime` 스크럽.
- 시퀀스: 넝쿨이 뻗어나감 → 후반부 포도알 그래픽이 하나씩 등장 → 마지막에 타이틀 "Grapes are growing on the vine" + 서브카피 + 사이드바 등장.
- 스크롤 진행률 인디케이터 노출.
- Lenis로 부드러운 스크롤.
- 서브카피: *The compliments friends leave on my grapevine grow into grapes. Leave compliments that were hard to say face-to-face.*

### 5.2 About (`/about`)
- 배경에 포도알 4개 산포. 타이틀 + 설명 문단.
- 설명: *This is a compliment board to share with friends. Create your tree and share the link with your friends. Friends can add compliments to your board and help your grapes grow without logging in.*

### 5.3 How It Works (`/how-it-works`)
- **01~05 단계를 포도알 원 크기를 점점 줄여가며** 배치한 스케일 연출.
  1. Create My Grapevine
  2. Share link with your friends
  3. Waiting for friends' compliments
  4. A friend gave a compliment
  5. Grapes are growing!
- 장식 텍스트 `^_^`, `T.T`.

### 5.4 Login / Sign Up
- 원형 패널 중앙. ID / PASSWORD / Log in 버튼 / "Don't have an account? Sign Up".

### 5.5 My Vine (`/my`)
- **빈 상태:** 중앙에 `Create My Vine` 버튼 1개. (옵션 선택 없음)
- **생성 직후:** 리빌 연출 재생 → 판 노출.
- **판 상태:** 배경 넝쿨 이미지 위에 포도알 15개(고정 좌표). 빈 알 = 아웃라인/저채도, 채운 알 = 솔리드.
- 좌상단 `1/2 >` 페이지네이션. 채운 알 클릭 → See Grape 모달.

### 5.6 Share My Vine (모달)
- 딤 + 원형 패널. 타이틀 `Share My Vine`, 링크 필드 + `Copy` 버튼.

### 5.7 Setting (모달)
- 타이틀 `Setting`. 리스트: `My Account >` + 미정 4행(`...`). **미정 항목은 확정 전까지 비활성 표시.**

### 5.8 See Grape (모달)
- 작성자명(예: `Clara`, 익명이면 `Unknown`) + 칭찬 텍스트.

### 5.9 Other's Vine (`/v/{slug}`)
- 상단 `{주인이름}'s Vine`. 판 열람 (읽기 전용).
- 하단 CTA: 빈 슬롯 있음 → `Add Grape` / 이 페이지 꽉 참 → `Here is Full!`(비활성) + `>` 로 다음 페이지 유도.

### 5.10 Add Grape (모달)
- 타이틀 `Compliment {주인이름}`.
- 칭찬 입력(멀티라인), 하단에 **`Unknown` 라디오/체크(익명 토글)**, `Send` 버튼.
- 익명 미선택 시 이름 입력 필요.

## 6. 콘텐츠 (`data/`로 외부화)

| 파일 | 내용 |
|---|---|
| `data/slot-layout.ts` | **페이지당 15개 포도알의 고정 좌표 프리셋** (피그마 Ellipse 5002~5017에서 추출한 x/y/size, 컨테이너 대비 %). |
| `data/copy.ts` | 랜딩 3종 문구, CTA 라벨, 빈 상태·에러 메시지 전량. |

> 좌표를 코드에 하드코딩하지 않는다. 레이아웃을 바꾸고 싶을 때 `slot-layout.ts` 한 파일만 고치면 되도록 한다.

## 7. 핵심 규칙 (*동결 대상*)

1. **판(Vine):** 사용자당 1개. `Create My Vine` 시 Vine + Page 1(빈 슬롯 15) 생성. 생성 옵션 없음.
2. **페이지 용량:** 페이지당 **15알 고정**(피그마 좌표 프리셋 수와 일치). 전 페이지 동일 레이아웃.
3. **페이지 자동 증설:** 마지막 페이지의 15번째 알이 채워지는 **그 트랜잭션 안에서** 다음 페이지를 생성한다. 사용자는 판이 "끝났다"는 상태를 만나지 않는다.
4. **슬롯 점유는 원자적으로.** 링크 공유형이라 **두 방문자가 같은 슬롯을 동시에 누를 수 있다.** `(pageId, slotIndex)` 유니크 제약 + 충돌 시 "다른 알로 다시 시도" 재시도 플로우. **이 프로젝트에서 가장 놓치기 쉬운 규칙.**
5. **작성 권한:** 방문자는 **생성만** 가능. 수정·삭제 불가.
6. **익명:** `isAnonymous=true`면 작성자명을 저장하지 않고 표시는 `Unknown`. false면 이름 필수.
7. **주인 본인 작성:** 자기 판에는 작성 불가(로그인 세션의 ownerId와 slug 소유자가 같으면 CTA 비활성).
8. **칭찬 길이:** 최대 **80자**(부록 D 확인). 초과 입력 차단 + 카운터.
9. **판 상태 = 채운 수만.** 색 변화·완성 판정·축하·알림 **없음.**
10. **테스트:** 슬롯 점유·페이지 증설은 `now`/`slotIndex` 주입 가능하게 순수 함수로 분리 → 단위테스트.

## 8. 데이터 모델 (TypeScript, 순수 데이터)

```ts
type User = {
  id: string;
  loginId: string;        // 유니크
  displayName: string;    // "Blair" — 판 제목/모달 타이틀에 사용
  createdAt: string;
};

type Vine = {
  id: string;
  ownerId: string;        // User.id — 1:1
  slug: string;           // 공유 URL용, 추측 불가 랜덤 (예: 10자)
  createdAt: string;
};

type VinePage = {
  id: string;
  vineId: string;
  pageIndex: number;      // 1부터
  capacity: number;       // 15 고정
};

type Grape = {
  id: string;
  pageId: string;
  slotIndex: number;      // 0..14 — (pageId, slotIndex) UNIQUE
  authorName: string | null;  // isAnonymous면 null
  isAnonymous: boolean;
  message: string;        // <= 80자
  createdAt: string;
};

// 파생 (저장 X)
type PageView = {
  pageIndex: number;
  totalPages: number;
  slots: Array<{ slotIndex: number; grape: Grape | null }>;  // 항상 15개
  isFull: boolean;
};
```

- 슬롯 좌표는 **DB에 넣지 않는다.** `slotIndex` ↔ `data/slot-layout.ts`가 매핑.

## 9. 영상 · 모션 사양 (이 프로덕트의 핵심)

### 9.1 Main — 스크롤 스크럽

| 항목 | 값 |
|---|---|
| 라이브러리 | **Lenis** (부드러운 스크롤) |
| 제어 | 스크롤 진행률 `0..1` → `video.currentTime = p * duration` |
| 보간 | 직접 대입 금지. `current += (target - current) * 0.1` **lerp 필수** (안 하면 계단처럼 튐) |
| 영상 | 스크롤 영역 상단 `position: sticky` 로 pin |
| 오버레이 | 후반부 포도알 등장 / 타이틀 / 사이드바 — **DOM 레이어**를 진행률 구간에 매핑 (영상에 인코딩하지 않음, 수정 가능성 확보) |
| 인디케이터 | 스크롤 진행률 바 |

**영상 인코딩 (필수):** `currentTime` 스크러빙 품질은 **키프레임 간격이 전부**다. 일반 인코딩(GOP 250)이면 뚝뚝 끊긴다.

```bash
ffmpeg -i in.mov -g 1 -keyint_min 1 -c:v libx264 -crf 24 \
       -vf scale=1440:-2 -pix_fmt yuv420p -movflags +faststart out.mp4
```

- `-g 1` = 전 프레임 키프레임. 용량이 3~5배 늘어나므로 **해상도 1280~1440 + CRF로 상쇄**.
- 목표 용량: **15MB 이하**. 초과 시 길이를 줄이거나 해상도를 낮춘다.
- 필수 속성: `muted` `playsinline` `preload="auto"`.

**모바일 폴백 (🟡 부록 D):** iOS Safari에서 `currentTime` 스크러빙은 불안정하기로 악명 높다. 링크 공유형 서비스라 **유입 대부분이 모바일**이므로 대비가 필요하다.
→ 폴백: **이미지 시퀀스(WebP 60~120장) + `<canvas>`** 렌더. 안정적이지만 프리로드 전략 필요.

### 9.2 My Vine — 생성 리빌

- 트리거: `Create My Vine` 클릭.
- 재생 방식: **연속 재생이 아니라 초 단위로 끊어서(이산)** 재생 → 스톱모션처럼 넝쿨이 드러남.
- 구현: `requestAnimationFrame` 루프에서 목표 시간을 계단 함수로 양자화 (`Math.floor(t * steps) / steps`).
- 종료 후: 빈 포도판 상태로 전환.
- **Main과의 대비가 의도:** Main = 스크롤 종속 연속 스크럽 / My Vine = 클릭 트리거 이산 재생. 같은 소재, 다른 리듬.

### 9.3 붙이기 연출

- `Send` 성공 → 해당 슬롯에 포도알이 **위에서 톡 떨어져 붙는** 낙하 애니메이션.
- 기획 원문: *"실제 스티커판에 한 알을 채워 넣는 감각을 그대로 옮겼다."*
- duration/curve는 STEP에서 정확한 값으로 지정.

### 9.4 접근성

- `prefers-reduced-motion: reduce` → 스크럽/리빌/낙하 전부 정적 폴백(마지막 프레임 이미지 + 즉시 표시).

## 10. 백엔드 / 계정 전략 (🟡 핵심 결정 — 택1)

**전제:** 이 서비스는 **서로 다른 사람이 같은 판에 쓴다.** 로컬 저장으로는 성립 불가. 반드시 서버가 필요하다.

| | 경로 A — Supabase (권장·MVP) | 경로 B — Firebase |
|---|---|---|
| 인증 | Supabase Auth (email/password) | Firebase Auth |
| DB | Postgres + RLS | Firestore |
| 슬롯 유니크 | **`UNIQUE(page_id, slot_index)` 제약으로 DB가 보장** | 트랜잭션으로 직접 구현 |
| 페이지 증설 | RPC 함수 1개로 원자 처리 | 트랜잭션 |
| 비용 | 무료 티어 충분, SQL이라 규칙 표현 쉬움 | 무료 티어 충분, 규칙을 코드로 |

> **경로 A 권장 이유:** §7-4 슬롯 동시 점유가 이 프로덕트의 유일한 진짜 동시성 문제인데, Postgres 유니크 제약이 이걸 **한 줄로** 해결한다. Firestore는 같은 걸 트랜잭션 코드로 짜야 한다.
> 어느 쪽이든 데이터 계층은 **`repositories/` 인터페이스로 추상화**해 A↔B 교체 가능하게 설계한다.

## 11. 디자인 방향 (GRAPEVINE = 로우파이 · 타이포그래픽 · 사진 기반)

- **배경:** 실사 포도 넝쿨 사진/영상. UI가 그 위에 얇게 얹힌다.
- **타이포:** 모노스페이스 계열. 자간 넓은 대문자 아님, 코드 에디터 느낌의 담백함.
- **버튼:** 라운드 아웃라인 pill. 채움 없음, 얇은 보더.
- **포도알:** 단색 원(마젠타/퍼플 계열). 그라디언트·그림자 없음. 빈 알 vs 채운 알만 구분.
- **레이아웃:** 여백 크게, 좌상단 정렬 헤드라인 + 우상단 세로 사이드바. 중앙 정렬 지양.
- **모달:** 딤 오버레이 + 대형 원형 패널(그 위에 좌측 정렬 콘텐츠).
- **정확한 hex/폰트명은 피그마에서 추출해 STEP 10에 전달.** 추측 금지.
